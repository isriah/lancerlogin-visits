# LancerLogin Guest Visits plugin v0.3.0

Team lookup now runs on LancerLogin's shared FIRST connection. The FRC and FTC Events API usernames and tokens are saved once in **Settings > Integrations > FIRST**, and every module that looks up FIRST teams uses them. Typing a team number now also fills in the program and team name for FLL Challenge and FLL Explore teams, found with FIRST's public team search, which needs no credential. When a team is not found or lookup is not available, the guest chooses the program and types the name as before. The booking form now asks every guest for an approximate headcount.

Credentials already saved in Guest Visits move to **Settings > Integrations > FIRST** on their own, the first time Guest Visits runs after the update (a guest's team search, opening **Settings > Guest Visits > Team lookup**, or the notification job, which runs every five minutes). Nobody needs to enter them again. When LancerLogin already has a FIRST credential for a program, that one is kept. If a saved credential cannot be read, **Settings > Guest Visits > Team lookup** says so; save that program's username and token again in **Settings > Integrations > FIRST**.

This release needs a LancerLogin Core with module SDK 1.2.0 (`lancerlogin.core` `>=2.1.0-beta.3 <3.0.0` with `@lancerlogin/module-sdk` `^1.2.0`). Older Core releases are no longer supported. It adds migration 0004, which removes Guest Visits' own cache of FIRST's answers; LancerLogin's FIRST connection keeps its own.

## Bugs fixed

None.

## Features added

- Team lookup uses LancerLogin's shared FIRST connection, its cache and its per-visitor lookup limit. FRC and FTC credentials are managed in one place, **Settings > Integrations > FIRST**.
- FRC and FTC credentials saved in Guest Visits move there automatically.
- Team lookup finds FLL Challenge and FLL Explore teams too, with no credential. When one number is used in several programs, the guest picks their team. The programs read **FLL Challenge** and **FLL Explore** everywhere (guest page, staff pages, emails and the Guest visits report).
- The booking form's headcount is now **Headcount (approximate)** and required. The Worker refuses a new booking without one, and a guest cannot clear it later. Visits already saved without a headcount keep reading "Not given"; their guests can still change other details and add a headcount. Staff can still clear a headcount. No migration.
- The guest page calendar opens on this week: its top row is the week holding today, in the installation time zone, followed by four more weeks. The arrows still move five weeks at a time, and guests cannot page back before this week.
- The guest page heading always reads **Book a team visit**. Your team's name from **Settings > Guest Visits** still appears in guest emails and on the page for changing a visit.

## Features removed

- **Settings > Guest Visits > Team lookup** no longer saves or removes FIRST credentials. It shows whether lookup works and links to **Settings > Integrations**.
- Support for LancerLogin Core releases without module SDK 1.2.0.
- The **Require headcount** setting in **Settings > Guest Visits**, since every new booking now needs a headcount. Its stored value is kept, for older clients and backups, but no longer changes anything.
