# LancerLogin Guest Visits plugin v0.3.0

Team lookup now runs on LancerLogin's shared FIRST connection. The FRC and FTC Events API usernames and tokens are saved once in **Settings > Integrations > FIRST**, and every module that looks up FIRST teams uses them. Guests see no change: typing a team number still fills in the program and team name for FRC and FTC teams, and when a team is not found or lookup is not available, the guest chooses the program and types the name as before.

Credentials already saved in Guest Visits move to **Settings > Integrations > FIRST** on their own, the first time Guest Visits runs after the update (a guest's team search, opening **Settings > Guest Visits > Team lookup**, or the notification job, which runs every five minutes). Nobody needs to enter them again. When LancerLogin already has a FIRST credential for a program, that one is kept. If a saved credential cannot be read, **Settings > Guest Visits > Team lookup** says so; save that program's username and token again in **Settings > Integrations > FIRST**.

This release needs a LancerLogin Core with module SDK 1.2.0 (`lancerlogin.core` `>=2.1.0-beta.3 <3.0.0` with `@lancerlogin/module-sdk` `^1.2.0`). Older Core releases are no longer supported. It adds migration 0004, which removes Guest Visits' own cache of FIRST's answers; LancerLogin's FIRST connection keeps its own.

## Bugs fixed

None.

## Features added

- Team lookup uses LancerLogin's shared FIRST connection, its cache and its per-visitor lookup limit. FRC and FTC credentials are managed in one place, **Settings > Integrations > FIRST**.
- FRC and FTC credentials saved in Guest Visits move there automatically.

## Features removed

- **Settings > Guest Visits > Team lookup** no longer saves or removes FIRST credentials. It shows whether lookup works and links to **Settings > Integrations**.
- Support for LancerLogin Core releases without module SDK 1.2.0.
