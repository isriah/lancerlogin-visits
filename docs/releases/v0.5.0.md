# LancerLogin Guest Visits plugin v0.5.0

The Guest Visits workspace now says exactly which message failed and why, and Admins can retry or dismiss a failed Discord post. Guest Visits' notification job also fits the Cloudflare Workers Free plan's limits: it sends fewer messages at a time, and on a LancerLogin release with module SDK 1.6.0 it works in small scheduler steps that each stay under the Free plan's 10 ms CPU.

This release still installs on LancerLogin 2.1.0-beta.4 or later. On releases without module SDK 1.6.0 it sends up to five messages every five minutes instead. No migration and no setting changes; nobody needs to do anything after updating.

## Bugs fixed

- The failed message banner no longer says failed messages are retried every five minutes (they never were), no longer sends staff to Needs attention for Discord posts, and no longer counts a failure forever.
- A Discord post refused for a missing permission or an unknown channel now fails at once, instead of after eight attempts.
- A run of the notification job could go over the Workers Free plan's CPU and request limits. It now sends at most five messages per run, and on a LancerLogin release with module SDK 1.6.0 it does one small step per scheduler slice: one message per slice, up to 20 every five minutes.

## Features added

- Each failed Discord post (a booking post or the weekly summary) gets its own banner that names it and says why it failed: the Discord permissions the bot lacks in the channel (View Channel, Send Messages or Send Messages in Threads) when Guest Visits can work them out, otherwise which ones to check; a channel Discord cannot find, with a link to **Settings > Guest Visits > Discord**; or Discord's own message.
- Admins can **Retry** a failed Discord post (a booking post until its visit ends, a weekly summary within a day of its report time) or **Dismiss** it. Changing the Discord channel, or turning Discord messages on or off, resolves earlier failed posts without posting them late.
- Failed booking emails and Outreach records get their own banner pointing to **Needs attention**, and count only until staff handle them.

## Features removed

None.
