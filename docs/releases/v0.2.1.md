# LancerLogin Guest Visits plugin v0.2.1

Adding availability and booking a visit take fewer steps. Staff can start a new availability window from the day they pick on the calendar, the Repeats and Weekdays controls are easier to read, and switching between a weekly window and a single date keeps what you typed. Guests start with the whole open window and can leave headcount blank, unless an Admin requires it.

This release adds migration 0003, which allows an empty headcount and adds the **Require headcount** setting; existing bookings keep their headcounts. Entire-installation backups now use Guest Visits backup version 2. Older backups still restore, with **Require headcount** off. A backup made with this release cannot be restored into an installation that runs an older Guest Visits release.

## Bugs fixed

- Switching **Repeats** between **Every week** and **One date** on the **Add availability** card no longer resets the date to today. The date you entered carries over in both directions, and times and title stay as entered.
- The **Repeats** and **Weekdays** controls no longer sit in boxes with large gaps, and Saturday no longer wraps onto its own line.

## Features added

- On the Visits calendar, double-click a day, or press Enter on it, to open **Add availability** on that date. Selecting a day and then choosing **Add availability** also starts on that day.
- **Repeats** is a two-option switch, and **Weekdays** is one row of **Sun** to **Sat** buttons that fits on a phone.
- When a guest chooses a time slot, arrival and departure default to the whole open window. Guests can still change both.
- Headcount is optional for guests. Staff screens, emails, Discord messages, the weekly summary and reports show **Not given** when it is left blank, and Outreach records are unchanged. An Admin can turn on **Require headcount** in **Settings > Guest Visits > Guest page** to make it required again.
- The team name example now reads "FRC 321 RoboLancers".

## Features removed

None.
